Methods and strings

  • Learn to read and use Python's dot notation.
  • Include computed values in strings through f-strings.
  • Format computed values in strings through format specs.

Dot notation

In step 2 you met five primitive types. One thing every type has in common is that it has methods: operations a value of that type can perform. Methods are accessed with a dot.

  • valuewhat the method works on
  • dotjoins the value to the method
  • methodwhat to do to it
  • argumentswhat it needs in order to do it

Almost every method returns something. That is the call's return value, and the call becomes it. In the same way that 2 + 2 is 4, the call above is 'bikeable'. A method call is an expression, as step 1 uses the word.

And because the return value is itself a value, you can call a method on it too. Each call works on what the one before it returned:

"  Walk Score  ".strip()           # 'Walk Score'
"  Walk Score  ".strip().lower()   # 'walk score'

The value itself is never changed. Text is immutable in Python: name.upper() returns a new piece of text and leaves name exactly as it was. Writing name.strip() on a line of its own therefore does nothing useful. You have to keep what it returns.

Tip 💡: read it left to right

A method call reads in that order: take this value, do this to it, using these. Then return the result.

The parentheses surrounding the argument list have an effect. The method name identifies which code to run. The parentheses make Python run it. They are there even when the argument list is empty:

"walkable".upper()   # 'WALKABLE'
"WALKABLE".lower()   # 'walkable'

Argument

A value given to a method so it can do its work. Arguments go inside the parentheses, separated by commas.

How many a method needs depends on how much information it needs beyond the value:

"walkable".upper()                   # 'WALKABLE'   needs nothing — the value is enough
"walkable".count("a")                # 2            needs to know what to count
"walkable".replace("walk", "bike")   # 'bikeable'   needs what to replace, and what with

Where a method takes more than one, their order determines which is which. Swap them and the call means something different. Here the swapped call changes nothing, and reports no error:

"walkable".replace("bike", "walk")   # 'walkable'   there is no "bike" in it to replace

Give a method the wrong number of arguments and Python raises an error immediately:

"walkable".upper("x")
TypeError: str.upper() takes no arguments (1 given)

Leaving the parentheses off

"walkable".upper     # <built-in method upper of str object>
"walkable".upper()   # 'WALKABLE'

Without parentheses Python will return the method itself rather than executing the code defined in the method. It does this without an error. If a value prints as something about a "method", this is what happened.

Which methods exist

They belong to the type, not to the value. Every piece of text has the same set. A number has a different set.

"18".upper()    # '18'
(18).upper()    # AttributeError: 'int' object has no attribute 'upper'

Learn to recognise that error early. It rarely means you typed the name wrong. It usually means the value is not the type you thought it was, which is the mistake from step 2 in another form.

Two forms that do similar jobs

len("18") is a function, given a value. "18".upper() is a method, belonging to one. Both take an input and return something. They differ in whether the value goes before the dot or inside the parentheses.

There is no rule to derive here. len is a function and upper is a method because that is how Python is arranged. You learn them as you meet them.

Putting values into text

Eventually you have some values and you want a piece of text with those values in it. It might be a label, a line of output or an identifier built from its parts.

The direct way is to join pieces together with +:

name = "Meridian-Kessler"
score = 14.5

"Walkability of " + name + " is " + str(score)
# 'Walkability of Meridian-Kessler is 14.5'

That works, and it is hard to write and to read. You are counting quotes and spaces, the sentence is broken into five pieces, and every value that is not already text needs str() around it. Forget one and you get:

TypeError: can only concatenate str (not "float") to str

String interpolation

Writing out the text you want, with gaps in it, and letting values fill the gaps when the line runs. The template stays readable because it looks like the result.

f-string

Python's way of doing that. An f before the opening quote, and an expression inside each pair of braces.

f"Walkability of {name} is {score}"
# 'Walkability of Meridian-Kessler is 14.5'

You get three things without extra work. The line now looks like what it produces, so you can check it by reading it. Values are converted for you, so you do not need str(). And anything can go in the braces, because what is in there is an expression:

f"{bike} of {workers} cycle"
f"{bike / workers}"
f"{name.upper()}"

Format spec

Instructions for how to write a value down, written after a colon inside the braces. They change how it appears, never what it is.

Say you want the bike share as a percentage, to one decimal place. You can do that yourself:

share = bike / workers        # 0.016116653875671526
percent = round(share * 100, 1)   # 1.6  — round() cuts it to one decimal
line = f"{percent}%"              # '1.6%'

Or you can say the same thing in a spec, and let the f-string do it:

line = f"{bike / workers:.1%}"    # '1.6%'

.1% is not something to look for

It reads like text you are searching for. It is not. It is two instructions:

  • %: write this as a percentage, which multiplies by 100 and adds the sign
  • .1: keep one digit after the decimal point

Nothing in a spec is text. Every character in it is an instruction, which is why a spec is short and hard to guess.

  • fmarks the text as a template, so braces mean something
  • expressionworked out first, then written into the text
  • :separates the value from how to write it
  • format spechow to write it: decimals, percent, padding, separators

Two stages, always in that order. The expression is worked out first, and only then does the spec set how the answer is written. That is why .1% means "as a percentage to one decimal" for any number, whatever expression produced it.

The specs you will use most often

Percentage

% multiplies by 100 and adds the sign. The digit after the dot is how many decimal places to keep.

share = 0.01612
f"{share:.1%}"   # '1.6%'
f"{share:.0%}"   # '2%'

Fixed decimals

f writes a fixed number of digits after the decimal point, rounding to fit. The digit after the dot is how many.

f"{share:.4f}"     # '0.0161'
f"{14.4667:.1f}"   # '14.5'

Thousands separator

A comma puts one between every three digits.

f"{1303:,}"   # '1,303'
f"{21:,}"     # '21'      nothing to separate

Width and alignment

A number is how many columns the value takes up. > puts the value at the right of them and < at the left. The gap is filled with spaces.

f"{14.5:>8}"          # '    14.5'
f"{'3101.03':<10}|"   # '3101.03   |'
f"{14.4667:>8.1f}"    # '    14.5'      width first, then decimals

Padding with zeros

A character written before > fills the gap instead of spaces. With 0 there, a number comes out at a fixed width with zeros in front.

f"{7:0>3}"     # '007'   3 columns, pushed right, gap filled with 0
f"{340:0>3}"   # '340'   already 3 wide, so nothing is added

A spec for debugging

f"{workers=}" prints workers=1303: name and value together. It is the shortest way to print a name with its value, and you will use it often in step 11.

Indexing and slicing

A string is a sequence of characters, indexed from zero. A slice s[a:b] takes from a up to but not including b, so the length of the slice is always b - a. That half-open convention is the same one that range and array slicing follow. Learn it now, and do not try to work around it.

geoid = "180973401103"
geoid[0:2]    # '18'      state
geoid[2:5]    # '097'     county
geoid[5:11]   # '340110'  tract
geoid[11:]    # '3'       block group
geoid[-1]     # '3'       negative indices count from the end

Tip 💡: look it up rather than guessing

Text has 47 methods, and the table above shows the few this project needs. Few people know the rest from memory. The list is written down:

  • docs.python.org: string methods, the whole set with what each one does.

Knowing that a method probably exists, and where to check, is more useful than remembering its name.
