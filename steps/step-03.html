Strings and formatting

  • Values can do things to themselves. That is what a dot means.
  • Text can be cut apart by position.
  • Numbers can be printed the way a person would write them.

Dot notation

In step 2 you met five primitive types. One thing every type has in common is the ability to carry methods: things a value of that type knows how to do. Methods are accessed with a dot.

  • valuewhat you are asking
  • dotjoins the value to the method
  • methodwhat to do to it
  • argumentswhat it needs in order to do it

The brackets are always there, even when nothing goes inside them:

"walkable".upper()   # 'WALKABLE'
"WALKABLE".lower()   # 'walkable'

Argument

A value handed to a method so it can do its work. Arguments go inside the brackets, separated by commas.

How many a method needs depends on how much it cannot work out for itself:

"walkable".upper()                   # 'WALKABLE'   needs nothing — the value is enough
"walkable".count("a")                # 2            needs to know what to count
"walkable".replace("walk", "bike")   # 'bikeable'   needs what to replace, and what with

Where a method takes more than one, their order is what says which is which. Swap them and you have asked a different question — one that here quietly does nothing at all:

"walkable".replace("bike", "walk")   # 'walkable'   there is no "bike" in it to replace

Give a method the wrong number of arguments and it says so immediately:

"walkable".upper("x")
TypeError: str.upper() takes no arguments (1 given)

Leaving the brackets off

"walkable".upper     # <built-in method upper of str object>
"walkable".upper()   # 'WALKABLE'

Without brackets Python will return the method itself rather than executing the code defined in the method. It does this without complaint. If a value prints as something about a "method", this is what happened.

Which methods exist

They belong to the type, not to the value. Every piece of text has the same set; a number has a different set.

"18".upper()    # '18'
(18).upper()    # AttributeError: 'int' object has no attribute 'upper'

That error is worth recognising early. It rarely means you typed the name wrong. It usually means the value is not the type you thought it was, which is step 2's trap wearing a different coat.

Two shapes that do similar jobs

len("18") is a function, handed a value. "18".upper() is a method, belonging to one. Both take an input and give something back; they differ in whether the value goes before the dot or inside the brackets.

There is no rule to derive here. len is a function and upper is a method because that is how Python is arranged. You learn them as you meet them.

Indexing and slicing

A string is a sequence of characters, indexed from zero. A slice s[a:b] takes from a up to but not including b, so the length of the slice is always b - a. That half-open convention is the same one that makes range and array slicing behave, and it is worth accepting early rather than fighting.

geoid = "180973401103"
geoid[0:2]    # '18'      state
geoid[2:5]    # '097'     county
geoid[5:11]   # '340110'  tract
geoid[11:]    # '3'       block group
geoid[-1]     # '3'       negative indices count from the end

f-strings

An f before the quotes makes every {...} an expression to evaluate and insert. After a colon comes a format spec, which is a tiny language of its own and the reason f-strings replace everything that came before them.

The specs you will use constantly:

share = 0.01612
f"{share:.1%}"        # '1.6%'    percent, one decimal
f"{share:.4f}"        # '0.0161'  fixed decimals
f"{1303:,}"           # '1,303'   thousands separators
f"{14.5:>6.1f}"       # '  14.5'  right-aligned in 6 columns
f"{'3101.03':<10}|"   # '3101.03   |'  left-aligned, for tables

The debugging one

f"{workers=}" prints workers=1303 — name and value together. It is the fastest print-debugging tool in the language and you will use it in step 12 more than you expect.

Build a GEOID where the state arrives as the integer 1 and confirm it comes out as 01…

f"{1:0>2}" gives '01', and so does str(1).zfill(2). Both work; the f-string version reads better inside a larger template.

What you cannot do is str(state).zfill(2) where state came from int(geoid[:2]) of a GEOID you already damaged — padding restores the width but not the information. If a GEOID has already been through int(), you cannot always tell whether 1073 was Alabama county 073 or state 10 county 73. The zero has to survive from the source.
