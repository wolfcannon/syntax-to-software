Tip 💡: None has a special meaning

In Python, None is a distinct concept that can be used to indicate data is missing, or that a name exists but a value has not yet been assigned to it.

Assignment binds a name to a value

workers = 1303 does not put 1303 into a box called workers. It makes the name workers refer to the value 1303. Rebinding it to something else is free and has no effect on the old value:

workers = "1303"     # a string
workers = int(workers)   # now the name refers to an int; the string is gone

Names have no declared type, so nothing stops a name from meaning a string on line 1 and an integer on line 2. That flexibility is why the next section is dangerous.

Three kinds of division

1303 / 8     # 162.875   true division, always a float
1303 // 8    # 162       floor division, discards the remainder
1303 % 8     # 7         the remainder itself

Use / for shares and rates. // and % come up when you are chopping fixed-width identifiers apart, which is exactly what a GEOID is.

Floats are approximate

0.1 + 0.2 is 0.30000000000000004. Binary floating point cannot represent 0.1 exactly, any more than decimal can represent 1/3. So never write if share == 0.05; write if abs(share - 0.05) < 1e-9 — near enough, rather than exactly equal. This bites in step 6, when a walkability score lands right on a category boundary.

The trap this whole project turns on

A GEOID is the Census Bureau's identifier for a geography. For a block group it is twelve characters: state, county, tract, block group, glued together. It looks like a number. It is not a number.

The rule

If you will never do arithmetic on it, it is an identifier, and identifiers stay str. Zip codes, FIPS codes, GEOIDs, phone numbers, ISBNs. The test is not "does it look like a number" but "does adding two of them together mean anything".

Why is a GEOID a str when it looks like a number?

Because its digits are positional labels, not a quantity. Three consequences follow:

  • Leading zeros are meaningful, and integers cannot carry them.
  • Arithmetic on it is meaningless — no GEOID is "twice" another one.
  • Joining two datasets is equality of labels, and "01073..." is not equal to 1073....

The reason this is worth a whole section is the failure mode: nothing raises. Rows just quietly stop matching, your sample shrinks, and your correlation changes for a reason that has nothing to do with the world. Step 18 writes the test that pins this down permanently.
