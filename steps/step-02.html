Tip 💡: None has a special meaning

In Python, None is a distinct concept. It can be used to indicate data is missing, or that a name exists but a value has not yet been assigned to it.

Assignment

The statement you will write most: a name, an =, and a value.

workers = 1303
score = 14.5
label = "walkable"

Python works out the value on the right, then binds the name on the left to it. Nothing is printed. The effect is the point.

The = is an instruction. It does not test whether two things are equal. That is ==, and it comes in step 4, Blocks and conditions.

Casting

Converting a value from one type to another. Each type name is also a way to produce a value of that type.

int("1303")     # 1303     text becomes a whole number
float("14.5")   # 14.5     text becomes a number with a fraction
str(1303)       # "1303"   a number becomes text

Casting does not change the value you gave it. It produces a new one, and the original stays as it was.

Learn two cases now, because both look like mistakes the first time you see them:

int(14.9)       # 14       it cuts the fraction off, it does not round
int("14.5")     # ValueError: invalid literal for int()

The second one raises an error because there is no whole number written in "14.5". Write float("14.5") and you get 14.5. Write int(float("14.5")) and you get 14. Your code now states that you want the fraction discarded.

Referential binding

A name does not contain a value. It refers to one.

workers = "1303"
workers = int(workers)

Three kinds of division

1303 / 8     # 162.875   true division, always a float
1303 // 8    # 162       floor division, discards the remainder
1303 % 8     # 7         the remainder itself

Use / for shares and rates. // and % are for splitting a fixed-width code into parts: the first two digits, the last two digits. You do that in exercise 3.

Floats are approximate

0.1 + 0.2    # 0.30000000000000004

A computer stores a float in binary and cannot write 0.1 exactly, in the same way you cannot write 1/3 exactly as a decimal.

So a float you computed can differ from the one you typed in its last digits. Never test whether a computed float is exactly equal to another float. That gives a wrong result in step 4, Blocks and conditions, when a score is exactly on a category boundary.

The mistake that matters most in this project

A GEOID is the Census Bureau's identifier for a geography. For a block group it is twelve characters: state, county, tract, block group, joined together. It looks like a number. It is not a number.

The rule

If you will never do arithmetic on it, it is an identifier, and identifiers stay str. Zip codes, FIPS codes, GEOIDs, phone numbers, ISBNs. The test is not "does it look like a number" but "does adding two of them together mean anything".

Two tools let you check a GEOID. len counts its characters. == asks whether two values are equal, and gives True or False. Comparisons are covered in step 4, Blocks and conditions.

geoid = "180973401103"
len(geoid)                  # 12
geoid == "180973401103"     # True
geoid == "180970000000"     # False

Tip 💡: deciding whether something is a number

Ask what adding two of them together would mean.

  1. Two counts add up to a bigger count. It is a number.
  2. Two scores average to a meaningful score. It is a number.
  3. The sum of two zip codes means nothing. It is text, and it stays text.

Getting this wrong raises no error. Rows stop matching, with no message. Your results then change for a reason that is not in the data.
