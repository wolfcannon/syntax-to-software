Comprehensions

  • A loop that builds a list, written on one line.
  • The same three pieces, moved left to right.
  • Shorter is not always clearer — and there are cases it cannot express at all.

The same loop, said once

Four lines that build a list collapse into one:

shares = []
for row in joined:
    shares.append(row["bike"] / row["workers"])

shares = [row["bike"] / row["workers"] for row in joined]

The order reads awkwardly at first, because the value you are collecting comes before the loop that collects it. It is the same three pieces you already write, moved onto one line:

Read a comprehension by finding the for first. Everything to its left is what you are collecting, everything to its right is where the values come from and which ones to keep.

Three brackets, three types

[f(x) for x in xs]          # list — ordered, duplicates kept
{k: f(k) for k in keys}     # dict — the lookup from step 7, in one line
{x["geoid"] for x in rows}  # set — unordered, deduplicated, fast membership

Dict comprehensions are the natural way to build a lookup:

walk_lookup = {r[0] + r[1] + r[2] + r[3]: float(r[4]) for r in walk_raw[1:]}

Duplicate keys don't complain

If two rows produce the same key, the later one silently wins and your lookup is quietly shorter than your input. Comparing len(lookup) with len(rows) after building it is a one-line check worth making a habit — and it is what catches a duplicated GEOID in the real file.

Sets answer the join questions directly

Step 7 needed two loops to find the unmatched rows on each side. As sets it is one operator each, and it reads like the question:

acs_ids = {row["geoid"] for row in acs_rows}
walk_ids = set(walk_lookup)          # a dict yields its keys

unmatched = acs_ids - walk_ids       # asked for, never scored
orphans   = walk_ids - acs_ids       # scored, never asked for
both      = acs_ids & walk_ids       # the actual analysis sample

Membership in a set is fast in the way dictionary lookup is fast, so if geoid in walk_ids stays cheap no matter how large the data gets. The same test against a list scans it from the start every time — fine for 632 rows, ruinous for the 220,000 block groups in the national file you get to in the capstone.

When a loop is the better answer

A comprehension builds one collection from one source. Reach for a loop when you are doing anything else:

  • Building several things at once, or counting as you go.
  • Anything with try/except in it — you cannot put one inside a comprehension, and step 12 will want to.
  • When the line stops fitting on one line. A comprehension with two fors and a conditional expression is not clever, it is a loop wearing a disguise.

How many block groups failed to join, and why might that be?

In the sample: one ACS row with no walkability score, one scored block group no ACS row asked for. In the full data in data/: 5 and 7.

Plausible reasons, and they are all real:

  • The EPA excludes block groups with no population or no households — parks, airports, industrial land, water.
  • The two datasets were cut from census geography at slightly different times, so a block group split or merged in between.
  • A block group exists in the ACS release but had no reportable estimates.

What is not a reason here is the leading-zero bug, because Indiana is state 18. That is exactly why it stays invisible until step 20 — the join rate looks fine, so nobody checks.
