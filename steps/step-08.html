Comprehensions

  • A loop that builds a list, written on one line.
  • The same three pieces, moved left to right.
  • Shorter is not always clearer. There are cases it cannot express at all.

The same loop in one line

The examples on this page use joined, the list that step 7's exercise 3 built. It holds one dictionary per ACS row:

joined[5]    # {'geoid': '180973401103', 'workers': 1303, 'bike': 21, 'walk_index': 14.5}
len(joined)  # 11

You can write four lines that build a list as one line:

shares = []
for row in joined:
    shares.append(row["bike"] / row["workers"])

shares = [row["bike"] / row["workers"] for row in joined]

Both versions stop with ZeroDivisionError on the row with no workers. The figure below adds the condition that skips it.

The order is unfamiliar at first, because the value you are collecting comes before the loop that collects it. It is the same three pieces you already write, moved onto one line:

Read a comprehension by finding the for first. Everything to its left is what you are collecting, everything to its right is where the values come from and which ones to keep.

The condition after if can join several tests with and. A row is kept only when every test is true:

busy = [row["geoid"] for row in joined if row["workers"] > 1000 and row["bike"] > 0]
busy    # ['180973401103']: two rows have over 1000 workers, one has no cyclists

A comprehension also gives you the list to average. sum adds it up and len counts it:

workers = [row["workers"] for row in joined if row["walk_index"] is not None]
sum(workers) / len(workers)    # 573.9: the mean worker count of the 10 matched rows

Three brackets, three types

[f(x) for x in xs]          # list — ordered, duplicates kept
{k: f(k) for k in keys}     # dict — the lookup from step 7, in one line
{x["geoid"] for x in rows}  # set — unordered, deduplicated, fast membership

Dict comprehensions are the usual way to build a lookup:

walk_lookup = {r[0] + r[1] + r[2] + r[3]: float(r[4]) for r in walk_raw[1:]}

Duplicate keys raise no error

If two rows produce the same key, the later value replaces the earlier one, and Python reports no error. Your lookup then has fewer entries than your input has rows. Comparing len(lookup) with len(rows) after building it is a one-line check. Make it every time. This check detects a duplicated GEOID in the real file.

Answer the join questions directly with sets

Step 7 needed two loops to find the unmatched rows on each side. With sets, each side needs one operator, and the code has the same form as the question:

acs_rows = [dict(zip(acs_raw[0], r)) for r in acs_raw[1:]]
acs_ids = {r["state"] + r["county"] + r["tract"] + r["block group"] for r in acs_rows}
walk_ids = set(walk_lookup)          # walk_lookup from the section above. A dict yields its keys

unmatched = acs_ids - walk_ids       # {'180973103083'}: asked for, never scored
orphans   = walk_ids - acs_ids       # {'180973201071'}: scored, never asked for
both      = acs_ids & walk_ids       # 10 GEOIDs: the actual analysis sample

A membership test on a set is fast for the same reason that a dictionary lookup is fast. So if geoid in walk_ids stays fast for data of any size. The same test against a list scans it from the start every time. That is fast enough for 632 rows. It is too slow for the 220,000 block groups in the national file that you use in the capstone.

When a loop is the better answer

A comprehension builds one collection from one source. Use a loop when you are doing anything else:

  • Building several things at once, or counting as you go.
  • Anything with try/except in it. You cannot put one inside a comprehension, and step 12 needs one.
  • When the code no longer fits on one line. A comprehension with two fors and a conditional expression is harder to read than the loop it replaces.

In the sample: one ACS row with no walkability score, one scored block group that matches no ACS row. In the full data in data/: 5 and 7.

Plausible reasons, and they are all real:

  • The EPA excludes block groups with no population or no households: parks, airports, industrial land, water.
  • The two datasets were made from census geography at slightly different times, so a block group split or merged in between.
