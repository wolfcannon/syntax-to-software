Tuples, lists, and ranges

  • A list holds values in order, and can be changed.
  • A tuple is one thing with a fixed number of parts.
  • A range counts for you without storing the numbers.

List

An ordered collection of values, written in square brackets. Every value so far has been one thing; a list is however many you like, kept in order.

scores = [3.5, 14.5, 9.0]

scores[0]      # 3.5    the first, counting from zero
scores[2]      # 9.0    the third
scores[-1]     # 9.0    the last, counting from the end
len(scores)    # 3      how many there are

Indexing and slicing work exactly as they did on text in step 3. A slice scores[a:b] runs from a up to but not including b, so its length is always b - a.

Adding and removing

A list can be changed after it exists, which is the main reason to choose one.

scores.append(19.5)   # puts 19.5 on the end
scores.pop()          # takes the last one off and hands it back
scores.pop(0)         # or the one at a position

append changes the list in place and hands back nothing. pop changes it in place and hands back the value it removed.

The one that catches everyone

scores = scores.append(19.5) looks reasonable and destroys your list. append has already done its work by changing the list; what it hands back is None, and that is what the name now refers to.

Call it on its own line. The same applies to every method that changes a list in place.

Tuple

A fixed group of parts, written in round brackets, which cannot be changed once made.

pair = ("180973401103", 14.5)

geoid, score = pair    # unpacking: one name per part
pair[0]                # '180973401103'

The difference from a list is not really about brackets:

  • A list is a collection of things of the same kind, however many there happen to be. You add to it and take from it.
  • A tuple is one thing with several parts, and the number of parts is fixed by what it means. There is no sensible way to append a third item to a pairing.

Being unchangeable also makes a tuple usable as a dictionary key, which is step 8.

Range

A sequence of whole numbers, produced as they are needed rather than stored.

range(5)         # 0, 1, 2, 3, 4
range(2, 6)      # 2, 3, 4, 5
list(range(5))   # [0, 1, 2, 3, 4] — if you really want them

Half-open again: range(5) stops before 5, and has 5 numbers in it. A range is for counting, not for holding data, and step 7 is where counting starts being useful.

Exercises

Tip 💡: picking the right one

  1. Will it grow or shrink? List.
  2. Is it one thing with named parts that always come together? Tuple.
  3. Do you just need the numbers 0 to n? Range — and do not turn it into a list unless something makes you.
