Functions

This step gives names to three ideas that you have written out by hand many times. After this step, your working code is a set of named functions that later steps build on.

Definition, arguments, return

def bike_share(bike, workers):
    """Fraction of workers who commute by bicycle, or None if unknowable."""
    if workers == 0:
        return None
    return bike / workers

bike_share(21, 1303)    # 0.016116653875671526
bike_share(4, 0)        # None

Three things in three lines. The docstring is the first statement in the body and is what help(bike_share) prints. Write it as a sentence about what comes out, not a restatement of the name. return ends the call immediately. The second return is reached only when the first was skipped. A function that reaches the end of its body without a return gives back None. That is a real source of confusion when you meant to return something.

One function calling another

A function can call any function defined before the call runs. mean_share calls bike_share once per row:

def mean_share(rows):
    """Mean bicycle share over (bike, workers) pairs, skipping unknowable ones."""
    shares = []
    for bike, workers in rows:
        share = bike_share(bike, workers)
        if share is not None:
            shares.append(share)
    return sum(shares) / len(shares)

mean_share([(21, 1303), (3, 184), (4, 0)])    # 0.01621050085087924: (4, 0) is skipped

sum(shares) / len(shares) is the mean: the total divided by how many values there are.

Default values and keyword arguments

A parameter written with = has a default value. A call that leaves that argument out gets the default. A call can also name the parameter it sets. That is a keyword argument.

def is_withheld(count, sentinel=-666666666):
    """True when a Census count is the code for a withheld estimate."""
    return count == sentinel or count < 0

is_withheld(-666666666)       # True: sentinel is -666666666, the default
is_withheld(21)               # False
is_withheld(-1, -1)           # True: -1 given by position
is_withheld(-1, sentinel=-1)  # True: -1 given by name

or is true when either side is true, so any negative count also gives True:

-5 == -666666666 or -5 < 0    # True: the second test is true

Pure functions

A pure function's answer depends only on its arguments, and it changes nothing outside itself. bike_share(21, 1303) is 0.0161 today, tomorrow, and anywhere else you call it, regardless of what ran before it.

The rest of this course depends on that property. A pure function can be tested in isolation (step 19). It can be swapped for an equivalent implementation and checked (step 10). It can be moved into another file without any of the surrounding code (step 14). Impure code reads a global, or mutates a list its caller still holds. With impure code, each of those three tasks also needs the code around the function.

Default arguments are evaluated once

Default values are evaluated once, when the def runs. They are not evaluated again on each call. So def collect(rows=[]) shares one list across every call that omits the argument. Items that one call adds are still in the list on the next call. Use def collect(rows=None) and build the empty list inside. The cause of this fault is hard to find the first time it occurs.

Scope

The region of a program in which a name means something.

Every block you have written so far shared one set of names with everything around it. That holds for every if and every for. A name first assigned inside an if is still there afterwards. def is the first block that does not work that way.

A function has a scope of its own

Names assigned inside a function are local to it and stop existing when it returns. That is what lets you use score inside two different functions without them interfering.

A function can still read names from the surrounding program, which is convenient. It also lets a function depend on something defined elsewhere that its parameters do not show. The level-up examines that risk in detail. If a function needs a value, take it as an argument.

Padding text, counting and sorting

The exercises also need three small pieces. Step 3 padded numbers with 0>. It pads text the same way:

f"{7:0>3}"      # '007'
f"{'7':0>3}"    # '007': text pads the same way
f"{'097':0>3}"  # '097': already 3 wide, so unchanged

To count how often each value appears, keep a dictionary of counts. .get(label, 0) gives 0 the first time a label appears:

counts = {}
for label in ["Above Average", "Most Walkable", "Above Average"]:
    counts[label] = counts.get(label, 0) + 1
counts    # {'Above Average': 2, 'Most Walkable': 1}

Here a default of 0 is correct. A label that has not appeared yet has been counted zero times, which is a true count. Step 7's warning was about a missing score, which is not zero.

sorted gives a new list in order:

sorted(["180973417003", "180973103083"])    # ['180973103083', '180973417003']

Can each function be called in isolation, with made-up arguments, and give the right answer?

That is the complete test. Apply it on purpose. Start with an empty editor and call build_geoid("01", "073", "000100", "1") with no other code around it. See whether it works.

If it does, the function is self-contained. If it raises NameError, it was reading something from the surrounding code that is not a parameter. Examples are a header list, a lookup dict and a column index. That dependency needs to become a parameter.

Doing this by hand takes a long time, and that is the reason for step 19. A test file is this check, written once and run automatically every time. About forty such checks have run against your code in the steps so far.
