Unit 1 — Foundations · Step 4

Blocks and conditions

  • Lines that belong together run as one unit.
  • Indentation marks which lines those are.
  • A condition decides whether they run at all.

Block

A run of consecutive statements that belong together and are handled as one unit. All of them run, all of them run ten times, or none of them run. Python marks a block with indentation.

A block is always introduced by a line ending in a colon. That line says what the block is for, and the lines indented beneath it are its contents. Blocks nest, and the indentation is what tells you how deeply.

Indentation is syntax

Indentation is not presentation:

  • A colon opens a block.
  • The indented lines under it are the block.
  • Nothing closes a block. Change a line's indentation and you have moved it into a different block. It now runs at a different time, or a different number of times. That is not a style problem. It is a different program.

Two kinds of error

A syntax error means Python could not read your code as Python. Nothing runs. The broken line does not run, and neither do the lines above it. You find out the moment you run it, and you are told roughly where.

A logic error means your code is valid Python and does something other than what you meant. It runs, it produces an answer, and Python reports nothing, because Python found no error.

A misplaced indent can be either. Indent a line that opens a block and you get a syntax error. Indent a line inside a block and you usually get the second kind. That kind does more harm. The analysis produces a wrong number with no error message, and nobody questions it.

Comparing values

A comparison is an expression whose value is True or False.

score = 14.5

score < 5.75     # False   less than
score <= 5.75    # False   less than or equal to
score > 10.5     # True    greater than
score >= 14.5    # True    greater than or equal to
score == 14.5    # True    equal to: two equals signs
score != 14.5    # False   not equal to

One = assigns, as in step 2. Two == compares.

Comparisons join with and, or and not. and is true only when both sides are. or is true when either is. not turns True into False and False into True.

score = 14.5
bike = 0

score > 10.5 and bike > 0    # False   bike > 0 is False
score > 10.5 or bike > 0     # True    score > 10.5 is True
not score > 10.5             # False

Text cannot be compared with a number. This line is valid Python, so Python reads it. It stops with an error when the line runs:

"3.5" <= 5.75
# TypeError: '<=' not supported between instances of 'str' and 'float'

That is a third kind of error. It is not a syntax error, because Python could read the line. It is not a logic error, because Python reports it.

Tip 💡: reading an indentation error

  1. unexpected indent means a line is indented and nothing above it opened a block. Look at the line above for a missing colon.
  2. expected an indented block is the opposite: a colon opened a block and nothing was put in it.
  3. If an indent looks correct and Python reports an error, you have mixed tabs and spaces. They are invisible on screen. Use spaces.

Fix one thing and run again. The error changes as you go, and each new one is progress.

if / elif / else

Only the first matching branch runs, and elif is the reason. A chain of separate ifs can run more than one branch and give a different answer:

if score <= 5.75:
    label = "Least Walkable"
elif score <= 10.5:          # reached only if the first was False
    label = "Below Average"
else:
    label = "Above Average"

Because earlier branches have already excluded the lower ranges, each test only needs its upper bound. A lower bound as well, as in elif 5.76 <= score and score <= 10.5:, states a condition that is already guaranteed. A lower bound that you type can also leave a gap between two ranges. A score of 5.755 matches neither branch and is labelled Above Average, and no error reports the gap.

Truthiness

Python accepts almost any value as a condition. Zero is false, and so are 0.0, the empty string "", and None. Essentially everything else is true.

is None asks a different question: is the value None? It is true for None and for nothing else, so 0 gives False.

bike = None
bike is None      # True    no figure

bike = 0
bike is None      # False   0 is a figure

Where truthiness gives the wrong answer

A neighbourhood where nobody cycles has a bike count of 0. That is a figure, and if bike: treats it as though there were none:

bike = 0

if bike:
    print("counted")
else:
    print("no figure")    # this one runs — 0 is false

Ask whether the value is missing instead, and zero is kept:

bike = 0

if bike is not None:
    print("counted")      # this one runs — 0 is not None
else:
    print("no figure")

The first form reports every place where nobody cycles as having no figure, and it gives no error. Those are the places the question is about. Use is None when you mean missing. Use truthiness when you mean empty.

Tip 💡: every threshold has an edge — check it

  1. Whenever you write a threshold, ask what happens exactly at it. < and <= disagree on one value, and that value occurs more often than you expect.
  2. When you mean "no answer", write is None. When you mean "empty", truthiness is fine. They are different questions.
