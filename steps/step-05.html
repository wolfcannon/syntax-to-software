Conditions and truthiness

  • Ask a question, and run a block only when the answer is yes.
  • Only the first matching branch runs.
  • Almost any value can answer a question, which is a trap as often as a convenience.

Comparing values

A comparison is an expression whose value is True or False.

score < 5.75     # less than
score <= 5.75    # less than or equal to
score == 14.5    # equal to — two equals signs
score != 14.5    # not equal to

One = assigns, as in step 2. Two == asks.

Comparisons join with and, or and not. and is true only when both sides are; or when either is.

if / elif / else

Only the first matching branch runs, and elif is not decoration — a chain of separate ifs can fire more than once and give a different answer:

if score <= 5.75:
    label = "Least Walkable"
elif score <= 10.5:          # reached only if the first was False
    label = "Below Average"
else:
    label = "Above Average"

Because earlier branches have already excluded the lower ranges, each test only needs its upper bound. Writing elif 5.76 <= score <= 10.5 is not wrong, but it states a condition that is already guaranteed — and it is how gaps sneak in.

And remember floats are approximate

A score computed as (13 + 7 + 19 + 17) / 4 may not compare equal to the literal 14.0. When a boundary matters as much as this one does, test values either side of it rather than relying on exact equality. This is what makes step 18's parametrised boundary tests worth writing.

Truthiness

Python will treat almost anything as a condition. Zero is false, and so are 0.0, the empty string "", and None. Essentially everything else is true.

Where truthiness betrays you here

if bike: is not the same as if bike is not None:. A neighbourhood where nobody cycles has a bike count of 0, which is false — so the first form quietly throws away every such place, and those are precisely the ones the question is about.

Use is None when you mean missing. Use truthiness when you mean empty.

Exercises

Tip 💡: every threshold has an edge — check it

  1. Whenever you write a threshold, ask what happens exactly at it. < and <= disagree on one value, and that value turns up more often than you expect.
  2. Never test two computed floats for equality. Ask whether they are close enough.
  3. When you mean "no answer", write is None. When you mean "empty", truthiness is fine. They are different questions.
