Keywords, types, and syntax

A very small reserved vocabulary

Python reserves 35 words. You cannot use any of them as a name, and that is the whole of the language's fixed vocabulary — every other word you will meet, including print, len and int, is an ordinary name that happens to come pre-assigned.

Pick one to see what it does. The faded ones are real keywords this course never needs.

Syntax, statements, and expressions

Syntax

The rules that decide whether text is Python at all.

Syntax governs arrangement: which characters may follow which, where a colon is required, what must be indented. Python checks all of it before running any of it.

It says nothing about whether a program is correct. Code that obeys every rule can still provide an incorrect result.

Statement

One complete instruction. A program is a sequence of them, run in order.

The one you will write most is an assignment: bike = 21 binds a name to a value. It produces nothing. The effect is the point.

Expression

A piece of code that has a value: 21 / 1303, len(rows), bike > 0.

Expressions are what statements are built from.

Nothing is shown unless you ask

bike = 21 displays nothing — a statement has no value. bike / workers displays nothing either: the value is computed, then discarded. To see it, ask for it — print(bike / workers).

Blocks and scope

Block

A run of consecutive statements that belong together and are handled as one unit — run them all, run them ten times, run none of them. Python marks a block with indentation.

A block is always introduced by a line ending in a colon. That line says what the block is for, and the lines indented beneath it are its contents. Blocks nest, and the indentation is what tells you how deeply.

Scope

The region of a program in which a name means something.

A block is not a scope

A name first assigned inside an indented block is still there after the block ends. The block controlled whether and how often those lines ran, not which names survive them.

Only some blocks open a scope of their own: the ones introduced by def and class. That is step 8's subject. Until then, every block you meet shares one set of names.

Indentation is syntax

Indentation is not presentation:

  • A colon opens a block.
  • The indented lines under it are the block.
  • Nothing closes a block. Change a line's indentation and you have moved it into a different block — it now runs at a different time, or a different number of times. That is not a style problem. It is a different program.

Two kinds of wrong

A syntax error means Python could not read your code as Python. Nothing runs — not the broken line, not the lines above it. You find out the moment you run it, and you are told roughly where.

A logic error means your code read perfectly well and does something other than what you meant. It runs, it produces an answer, and nothing is reported, because from Python's side nothing went wrong.

A misplaced indent can be either. Indent a line that opens a block and you get a syntax error. Indent a line inside a block and you usually get the second kind, which is the expensive one — an analysis that produces a number nobody questions.

Reading a SyntaxError

A SyntaxError is raised before a single line of your code runs — Python could not even parse it. Two things about the message matter:

  • The caret ^ points at where the parser gave up, which is often after the real mistake. An unclosed bracket on line 4 reports an error on line 5.
  • So when the flagged line looks fine, look at the line above it.
  File "your code", line 3
    if score <= 5.75
                    ^
SyntaxError: expected ':'

Type

Every value has a type: what kind of thing it is. type() reports it.

type(1303)     # int — a whole number
type(3.5)      # float — a number with a fractional part
type("1303")   # str — text

1303 and "1303" are different values. The quotes are what make the second one text: a run of characters that happens to contain digits. You cannot do arithmetic with it.

A value that looks like a number need not be one, and nothing on screen will tell you which you have. type() will.

Exercises

Both of these are the code from the question above, with one thing wrong. Fix it and run.

Given a line with a misplaced colon or bad indentation, can you locate the problem from the error message?

The procedure, in order:

  1. Read the last line of the message — it names the category (expected ':', unexpected indent, '(' was never closed).
  2. Look at the reported line. If it is obviously fine, look at the line above — unclosed brackets and missing colons report late.
  3. For indentation errors, check whether you have mixed tabs and spaces. This is invisible on screen and is why everyone settles on four spaces.

A SyntaxError means nothing ran at all. That's actually the friendly case: no half-finished state, no partly-written file. Step 10 deals with the errors that happen while running, which are messier.
